# Race detector

`count++` — это не одна неделимая операция: значение нужно прочитать, увеличить и записать обратно. Если две goroutine делают это без синхронизации, обновление может потеряться.

Показывайте версии строго по порядку:

1. `01_initial`: обычный последовательный цикл без goroutine. Он всегда печатает `1000`; гонки здесь не может быть, так как исполнитель один.
2. `02_iteration_goroutines`: добавили goroutine и ненадёжный `Sleep`. Иногда число меньше 1000, а иногда `main` завершается слишком рано. Это плохой способ ждать результат.
3. `03_iteration_waitgroup`: `WaitGroup` гарантирует, что все goroutine завершились, но `count++` всё ещё конкурентно меняет общую память. Race detector по-прежнему ругается.
4. `04_iteration_mutex`: mutex защищает сам счётчик. Здесь `WaitGroup` и mutex решают разные задачи: один ждёт, второй синхронизирует доступ.

Показывайте через `go run -race`. Детектор сообщает о конфликтующих доступах на реально выполненном пути; отсутствие сообщения не доказывает отсутствия гонок во всей программе.
