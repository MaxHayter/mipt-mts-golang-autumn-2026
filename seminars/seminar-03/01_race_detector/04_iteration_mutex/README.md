# Шаг 4: Mutex защищает критическую секцию

## Запуск

```bash
go run ./01_race_detector/04_iteration_mutex
go run -race ./01_race_detector/04_iteration_mutex
```

Ожидаемый результат обеих команд: `count: 1000`; предупреждений race detector нет.

## Что сказать

- `mu.Lock()` разрешает войти в участок `count++` только одной goroutine; `Unlock()` открывает доступ следующей.
- `WaitGroup` отвечает за «дождаться всех», а `Mutex` — за «не менять общую память одновременно».
- Критическая секция должна быть маленькой: нельзя держать mutex во время сети, диска или длительных вычислений.

## Время

```bash
/usr/bin/time -p go run ./01_race_detector/04_iteration_mutex
/usr/bin/time -p go run -race ./01_race_detector/04_iteration_mutex
```

Mutex может сделать код медленнее при высокой конкуренции, но он делает результат корректным. Производительность обсуждают только после проверки корректности.
