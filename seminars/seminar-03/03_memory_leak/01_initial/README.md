# Шаг 1: маленький subslice удерживает большой массив

## Запуск и профиль

```bash
go run ./03_memory_leak/01_initial
go tool pprof -top memory-initial.pprof
```

Ожидается `HeapAlloc` около 30 MiB. В `pprof` ищите строку `main.main`: именно там выделяются 30 буферов по 1 MiB.

## Что сказать

- В cache сохраняется только один байт, но slice содержит указатель на исходный backing array.
- Поэтому GC видит достижимую ссылку и не имеет права освободить весь массив в 1 MiB.
- Это логическая утечка удержания: память не потеряна, но продолжает быть достижимой по ошибке программы.

## Время

```bash
/usr/bin/time -p go run ./03_memory_leak/01_initial
```

Время не показывает удержание памяти. Смотрим `HeapAlloc` и heap profile.
